# Jirka's Arc (repository, targets and identifiers still named GarminFood)

**Jirka's Arc** is the app's name since version 2.0 ([`rebrand-to-jirkas-arc`](openspec/changes/archive/2026-10-07-rebrand-to-jirkas-arc/)): the phone, the widget gallery, Siri and every screen say "Jirka's Arc". Only the display name, icon and text changed. The repository, the Xcode targets and scheme, the bundle ids (`com.mlcousek.garminfood`), the `garminfood://` URL scheme, the Keychain services, store paths and every path below keep the name **GarminFood** on purpose: on a free Personal Team a new bundle id would be a new app with none of the old data (see that change's design D1).

A personal iOS food-tracking app — fast logging, a streak, levels, challenges, a real design system — with Garmin Connect as the system of record, since no public Garmin API exists for writing nutrition data. Built against Garmin's private mobile API, on a free Apple developer account, with no Mac. It is also its owner's training hub: the training experience adds a Plan tab and a training-first Today. The food-first experience stays the default.

**Status (2026-10-09): a working app in daily use, version 2.0.** It is built by CI and sideloaded onto the owner's iPhone. 52 OpenSpec changes are done and archived under [`openspec/changes/archive/`](openspec/changes/archive/), and about 130 pull requests are merged. The GitHub repository is [`mlcousek/JirkasArc`](https://github.com/mlcousek/JirkasArc); it was renamed from `GarminFood`, and the old URL redirects. `ios/` is the Xcode project (generated by XcodeGen, built by GitHub Actions).

## Read this first

- [`openspec/config.yaml`](openspec/config.yaml): project context, hard constraints, Design & UX principles, and everything established by live-probing the owner's Garmin account and testing on a real device.
- [`CLAUDE.md`](CLAUDE.md): the architecture (the packages and what each owns) and the conventions. It is kept current; prefer it and the code over older notes.
- [`docs/guide/index.html`](docs/guide/index.html): an interactive guide to every screen, flow and gamification catalog, plus the [badge gallery](docs/guide/badges.html).
- **No paid Apple Developer Program.** The app ships on a free Personal Team. CI builds it on GitHub Actions macOS runners (free on this public repo); it is signed and installed locally with AltServer and AltStore.
- **There is no shared state between the app and its widget/Control extension.** No App Group and no Keychain Sharing (`errSecMissingEntitlement`, -34018). So widgets never show the app's data, and every Control or widget button that logs something runs inside the app.

## What has shipped

- **Food logging on Garmin.** Sign-in, a local-first outbox with reconciliation against Garmin, and logging, editing, copying and deleting entries. Also meal presets, favourites, custom foods and custom ingredients. Search is one Czech-aware search over your own foods, Garmin and Open Food Facts, with an offline Czech index and barcode scanning. Weight and water sync with Garmin.
- **Standalone mode.** The same app with no Garmin account; everything stays on the phone.
- **Gamification.** A streak with freezes and 150 levels. Challenges, daily challenges, weekly bingo and bosses. Achievements, secrets, journeys, records, collections, seasonal events, sport & body badges and supplements. Every badge has drawn art.
- **The training experience** (with the Obsidian vault connection). A Plan tab and a training-first Today. Morning check-ins with pain mode, plan edits, gates and load, race prep and results, training stats and training rewards. The app writes only its own event files and a weekly backup of its own data to the vault.
- **Everyday surfaces.** Controls, Home Screen and Lock Screen widgets (static, open-the-app) and App Shortcuts for Siri. Local reminders, an in-app diagnostics log, themes, a layout editor, an app icon picker, trends, day notes, fasting and data export/import.
- **English and Czech** throughout.

## What remains unverified

- Write routes that are documented but have never been exercised against Garmin: `quickAddFoodLogEntry`, `bulkCreateFoodLogEntries` and `calculateGoals`. `createCustomMeal` is implemented but unconfirmed. Each one is gated behind an explicit user action, and its status is in [`docs/garmin-routes.json`](docs/garmin-routes.json). Sign-in, food logging, weigh-ins and water are confirmed on a real device.
- Everything visual is checked only on the owner's phone. There is no Mac, Simulator or Xcode preview in this workflow.

## Tools (read-only, already run against the live Garmin account)

- `tools/lib/garmin-auth.mjs` — OAuth1→OAuth2 exchange, lifted from the vault's working Node client.
- `tools/probe-garmin-nutrition.mjs` — reads its route list from `docs/garmin-routes.json` and reports Gate 0 status.
- `tools/discover-nutrition-routes.mjs` — wide route/parameter sweep; this is how `searchExpression` and `barCode` were found.
- `tools/garmin-get.mjs` — ad hoc authenticated GET against any path.

All four are GET-only. Run them with `VAULT_ROOT` pointed at the Obsidian vault holding the Garmin tokens:

```
VAULT_ROOT="/path/to/vault" node tools/garmin-get.mjs '/nutrition-service/food/search?searchExpression=banana'
```

See [`docs/garmin-routes.json`](docs/garmin-routes.json) for the full route registry and [`docs/garmin-food-log-contract.md`](docs/garmin-food-log-contract.md) for the write contract.
